## Концепции схемы моделей БД

1. Атомарная единица - Вариант ответа. (Answer). У нее нет ForeignKey.
2. Варианты ответов уникальны. Вопросы, могут содержать одни и те же ответы. Например, да или нет. По-хорошему, надо было бы еще constrain unique = 'text' добавить.
3. Так как order для моделей m2m так просто не добавить, были определены связующие m2m таблицы с доп колонкой order


## Дополнительные требования

Дополнительные требования, которые я принял, для упрощения реализации

1. Один пользователь может пройти опрос один раз.
2. Позволяем отвечать на один и тот же вопрос. Каждый ответ сохраняем. Не перезаписываем.
3. Ожидаем, что пользователь не будет отвечать на будущие вопросы, которые идут за текущим вопросом. Даже если ответить, нечего не сломается - ответит еще раз.
4. Ожидаю, что администратор не будет менять порядок вопросов опроса, который уже пользователи проходят.
5. Опросы строго линейны и не могут менять порядок вопросов в зависимости от ответов пользователя.
6. Требование про статистику я не совсем понял. Не успел пофантазировать. Подходы к ней зависят от конкретных требований.

# Описание ednpoint'ов

### GET /polls

Список всех доступных для прохождения опросов. Пройденный опросы сюда не входят. Если у сессии прохождения нет
current_question, то считаем сессию завершенной.

### GET /polls/<poll_id>/

Всегда редиректить на текущий вопрос в сессии прохождения - /polls/<poll_pk>/question/<current_question_pk>

### GET /polls/<poll_pk>/question/<question_pk>/

Возвращает данные по вопросу: Текст, допустимые варианты ответов и поддерживает ли вопрос, кастомный ответ пользователя.

### POST /polls/<poll_pk>/question/<question_ok>/answer/

Принимает в теле запроса {answer: <answer_pk>} или {text: 'кастомный текст ответа пользователя'} и сохраняет ответ пользователя.
В случае кастомного ответа, создается новый экземпляр ответа пользователя. Так же если еще нет экземпляра сессии 
прохождения, она создается тут же.

### Авторизация

Авторизация происходит с помощью указания в запрос заголовка X-User: <username> . Так просто и небезопасно ради упрощения.
Само собой это работает только для API запросов. В админку надо логиниться по честному с паролем.
